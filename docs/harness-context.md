# Harness context

## Private conversations

Each private conversation owns its EngineConfig, native session and history cursor. Creating one copies the selected private configuration once. It starts without another conversation’s history. The original private conversation retains its ID and stored context. Identity, memory, files, work directory and tool grants belong to the Bot. All tasks of one Bot run serially. Cancelling queued work preserves the remaining predecessor dependencies. Navigation does not stop execution. Stop and answers target the selected conversation.

Private conversation history search includes the same Bot’s other private chats and authorized team messages. Original tool evidence remains private to its session. Team and delegated contexts retain their existing boundaries. Cross-conversation search does not inject history into new native sessions.

## Ownership and admission

Domos stores Bot identity, complete chat, memories, attachments, and computer permissions. Pi Durable 1.4.0 stores submissions and tasks. Runtime.submit admits ordinary chat, additional input, routines, API requests, and CLI requests. Stable request IDs deduplicate retries.

The selected native Harness runs on the Bot's work computer. It owns generation, model context, and native tools. The driver registry includes Pi RPC, Codex app-server, Claude Code stream JSON, OpenCode ACP, Grok ACP, Antigravity ACP, Devin ACP, Cursor ACP, and custom ACP. UI choices come from the registry. Models and thinking levels come from the selected native program.

Grok uses `grok agent stdio` and the native account on the work computer. Its interjection extension retains message identity and image blocks. Rejected input waits for a later turn; uncertain input remains behind recovery. Native questions use stored question cards.

Antigravity uses the installed `agy acp`. Version 1.5.0 and later can replace a running prompt. The adapter retains every outstanding prompt and waits for the final response. A refused or unconfirmed addition retains its admission state.

Antigravity 1.5 and later report uncached input separately from cache reads. The adapter marks that basis before shared accounting and retains native counters. Usage settles in a separate transaction before task completion. Accounting errors produce a warning and cannot change the confirmed task result.

Devin admits mid-turn prompts only when the native capability is present. User-message echoes confirm acceptance. The final response supplies one usage record for the run. Its supported approval modes are accept edits, smart, and bypass. A single approval cannot switch the session into bypass.

Cursor uses the installed `cursor-agent acp` and its native login. It exposes native model and effort options, questions, plans, tasks and MCP configuration. Additional input waits for the next turn because its ACP driver has no confirmed steering receipt.

ACP context readings and USD cost counters retain their native values. Usage records calculate cumulative cost deltas without estimating missing amounts. Readable native compaction summaries enter the existing handoff path. Session loading resumes compatible contexts. Grok, Antigravity, Devin and Cursor cannot verify an interrupted turn's outcome through this adapter. Uncertain dispatch remains behind the recovery boundary and is not replayed.

Custom ACP uses the stable v1 SDK. The administrator supplies a program and arguments. Config options expose native model and thinking selectors. The adapter supplies Domos and managed MCP endpoints over HTTP when the Harness supports it. Otherwise, the work computer starts an official MCP SDK stdio transport to the same authenticated endpoints. It forwards requests, notifications, progress and cancellation. Each additional Harness needs a compatibility check before it is listed as supported. Draft ACP v2 is not enabled.

## Programs and accounts

Discovery resolves the program on the work computer. Inspection, login, and execution use that path and OS user. Existing native account files remain authoritative. Domos does not copy retained service credentials into native account files.

Absolute paths use filesystem checks. Windows selects an executable or command shim. POSIX checks execution permission and resolves login-shell commands. Missing programs, permission failures, and discovery failures remain distinct. Connection snapshots and persisted model catalogs serve the selector. Shared client state retains each Harness snapshot while a background check runs. Concurrent checks share an active request. Matching refreshes reuse the last result for three seconds. Failed discovery is not cached as an installation result.

Model and effort choices update the selector immediately. Saves run in order with the latest confirmed revision. A failed save restores the confirmed choice and reports the error. Chat dispatch waits for pending saves. Effort options come from the retained native model capabilities.

Claude model choices retain the CLI's selectable identifiers. Their labels include the native resolved model ID. Effort choices come from each entry's supported levels. Session controls match both the selectable identifier and the resolved ID. The native catalog determines which models are available.

First setup uses the saved configuration revision. A temporary readiness failure does not return a configured Bot to setup. Task dispatch still checks the work computer and native connection.

Downloads install a pinned package in the work computer's runtime directory. Node and npm must be available there. Existing installations stay in place. Installing an independent version does not activate it. Saving the selected model activates the resolved program. Configuration changes require an idle Bot.

Pi login uses its native ModelRuntime through an RPC extension. Codex and Claude use native login commands. OpenCode uses its local account API. Account state and secret input are transient. The native program stores credentials. Administrators manage programs and accounts. Paired clients can select available models in the Bot's configured Harness.

Codex, Claude, Pi, Grok, Antigravity, Devin and Cursor retain compatible connections between completed chat turns. Compatibility includes the program, account, directory, permissions, instructions and tool configuration. Each turn binds its own events, approvals, tools and cancellation. Idle connections close after ten minutes. Configuration and directory changes close idle connections. Stop terminates the active process tree. Memory review tasks keep separate native sessions. Uncertain outcomes still require recovery before more execution.

Chat shows waiting feedback when the client submits a message. The server's active task then owns that feedback, including native startup. Approval requests replace it with their own state. Failure and Stop settle the local feedback.

## History and migration

The forward migration keeps the current database. It sets migrated Bots to Pi and retains the current provider/model and thinking level. It settles old work and saves drafts as stopped messages. Missing native configuration requires user action. Migration does not silently select another model.

Switching Harness or work computer creates a native session. The display history remains continuous. Native session keys include the computer, configuration, and native account fingerprint. Native recovery checks recorded outcomes before deciding that a turn completed. Uncertain work is not sent again.

conversation_read uses query for keyword search in the owning computer's existing ChatDirectory index. Private sessions can search their Bot's private chat and current team memberships. Team sessions stay within that team. Delegated sessions cannot search private or team history. Search scopes apply before SQL pagination. Search before is an opaque search cursor; history before is an entry boundary. Matches retain entryId, conversationId, turnId when known, author, time and a bounded excerpt. Original reads check scope again. Shared reads use published chat only; other members' raw Work results remain private. Tool-result references in the current session's history point to the retained originals.

Handoff entries retain source conversation, entry, native task and turn identifiers when available, plus recorded file ownership and paths. omittedBytes counts omitted UTF-8 source bytes. omittedMessages counts excluded messages in the scanned window. scanLimitReached identifies a bounded scan, not a count of older records. Existing native summaries retain their own provenance and boundaries. Handoffs add no model requests. Missing context uses keyword search followed by original reads; important changes still require current file and evidence checks.

Handoffs contain quoted chat and retained summaries. Rebuilt sessions prioritize the opening user message, the two newest user messages in the recent window, the latest recorded plan, and up to four tool statuses. The recent scan reads up to 64 entries. A bounded scan at the start can recover the opening request. Long priority requests keep both ends. Each text excerpt has a 4000-byte limit. The packet has a 16000-byte limit. JSON escaping and metadata count toward the limit. Native recovery sends only messages after the confirmed receipt cursor. Historical images, private reasoning, tool arguments and raw outputs stay outside the packet. The receiving Harness can read the plan and complete tool records by entry ID through conversation_read.

Team handoffs combine published messages from that team’s member sessions. Delegated native contexts stay private. They retain authors and use the same packet limit. Native acceptance advances a separate team receipt cursor. Later native output does not advance this cursor. Additional input uses the same team cursor. conversation_read can read shared transcript entries from the current team. Other members’ tool records and private conversations remain outside that scope.

Native text, reasoning and tool records confirm receipt in the same accepted session, even when the turn later fails. The handoff cursor advances only through that confirmed range. Unconfirmed user input, stopped turns and terminal errors remain outside it. Compact operations retain their existing session boundary.

Compatible native sessions resume when only the model changes. Rebuilt sessions first use original chat that fits the handoff packet limit. Longer handoffs reuse a saved readable summary, its retained native chat, and newer original messages. Pi exports readable compaction summaries with their native boundary. Domos saves a separate conservative entry cursor before the current input. Native IDs are not Domos entry IDs. Summary metadata retains the source Harness, session, model and computer.

Rebuilt sessions dispatch with available summaries, bounded recent original messages and the current request. Native compaction supplies readable summaries for later handoffs. The context popover reports the delivered scope. Older details and original evidence remain available through conversation_read. Summaries do not verify artifacts or authorize replay of uncertain actions.

The conversation_read tool reads the complete stored record:

- `{ "query": "release" }` searches authorized chat. Use its `before` cursor with the same query for the next search page.
- `{}` reads a recent page. Pass its `from` cursor as `before` for older entries.
- `{ "entryId": 123, "offset": 0 }` reads a record in UTF-8 chunks. Follow `nextOffset` until null.

Each read belongs to the current Bot. Model-visible file references include fileId, ownerBotId, computer and source directory. Current submissions and attach_file receipts use the same reference fields. Handoffs keep references outside truncated message text; omitted records remain readable through conversation_read. A quoted team attachment owned by another Bot is not directly callable in the current Bot's tools: explicit collaboration sharing makes recipient-owned copies. File IDs, path content digests and characterId are separate identities. A delivered source image does not prove a requested edit succeeded. Native recovery reads are bounded separately. The original native session and Domos evidence remain on disk.

## Memory

Domos owns memory records. Each record belongs to one Bot unless the user shares it. User profile facts enter a fixed 8 KiB snapshot for one Durable task. Recovery and additional input reuse that snapshot. The next task reads current records and sends a changed snapshot in its request, without changing stable system instructions or replacing a compatible native thread. Work notes have a 24 KiB capacity and use memory_search or memory_list. Existing records remain work notes with their original text.

The memory tools are Domos product tools. Pi, Codex, Claude, OpenCode and ACP call the same storage and validation path through their existing native tool bridges. The model decides when to save. Manual writes use this service too. Confirmed tool writes commit independently of task completion. Evidence stores authorized conversation IDs, entry IDs and exact quotes. User facts require user messages; tool observations require tool evidence. Inference remains inference. `replaces` checks the target revision and preserves its scope. Known time is recorded at save; effective time needs explicit evidence. Memory text is data, not permission.

Background review is enabled by default. After ten successful user turns, Durable queues one task. It starts a separate native session and exposes only memory product tools with bounded recent history. It limits memory calls to 12 and stops after 120 seconds. It records native usage. It does not write review prompts or answers to displayed chat. Every review save creates a candidate; the user must confirm it. Review generation and record revisions reject stale proposals. Deletion retains minimal source and fingerprint tombstones. A review cannot extract the deleted source again. Foreground re-remembering requires a confirmed candidate. Deletion does not erase raw chat or a native model's existing context, and does not guarantee semantic forgetting. A new user turn cancels review. Users can disable review in the memory dialog. This task uses additional model calls.

`memory_search` accepts up to five alternative queries. Each query matches all its words. Missing memory matches fall back to the existing authorized chat index. Shared facts do not expose another Bot's private quotes. Source actions reuse chat navigation and Work. See [memory evals](memory-evals.md) for rule tests, browser acceptance and native evaluation.

OAuth callbacks use the configured public service URL. A remote client must be able to reach it. Providers without dynamic client registration require their own client information. External providers can charge for use. The application directory does not require Composio.

Avatar generation uses the existing image_generate purpose contract. purpose=avatar defaults to GIF and transparency; explicit static format skips animation, transparent=false preserves background. Model, prompt, frames, timing and key colour remain configurable within existing bounds. The worker retains processing parameters (without provider keys or reference base64) with originals, validates actual frames and transparency, and can resume local processing from those originals after restart without credentials or provider requests. Ready results associate purpose, actual media, original, final and cover. bot_update resolves the final file and cover from that receipt; raw uploads need preparation unless useOriginal=true explicitly reflects the user's request. Existing catalog media with unknown preparation status remain usable; known ordinary-image results require preparation or explicit original use. Generation never changes the active avatar. Candidate selection is requested through ask_question only when needed; an uploaded reference is already selected.


## Usage and subscription limits

Durable usage entries retain four separate counters: uncached input, cache reads, cache writes, and output. Native counters and their source remain attached. The conversation usage ledger commits cumulative counter advances and usage entries in one transaction. Counter scope includes the computer, account fingerprint, Harness and native session. Missing baselines and unconfirmed resets remain unknown. Finalized assistant usage and ACP cost updates retain confirmed consumption before failure or Stop.

UsageReader builds a disposable SQLite index from private, team and delegated conversations. Task markers include routine, memory and compaction work. Coverage counts tasks with missing usage separately from incomplete counters and missing prices. Historical records remain intact. Reliable cumulative amounts can repair derived totals; uncertain old counter baselines remain marked. Skill groups associate usage with tasks that called skill_read; they do not represent separate skill charges. CSV export uses the same filters and authorization as usage reads.

The price catalog stores verified date, model, context tier, cache duration and source. Native reported amounts remain distinct from standard API estimates. Missing tier, cache lifetime or price evidence prevents estimation. Neither value establishes the actual subscription bill.

Subscription reads use the owning computer's account. Codex uses account/rateLimits/read, Claude uses get_usage, and Grok uses _x.ai/billing. Cursor reads the native CLI login and queries cursor.com/api/usage-summary. Antigravity 1.1.11 and later runs its structured /usage command outside project directories, with automatic updates and browser launch disabled. Devin reads its web quota endpoint for the organization in DEVIN_ORGANIZATION (or DEVIN_ORG), with DEVIN_BEARER_TOKEN (or DEVIN_AUTHORIZATION) supplied in the owning OS user's environment. Devin CLI credentials are separate from web sessions. These credentials stay in the work process; clients receive only quota results. Pi, OpenCode and custom ACP have no quota reader. Unsupported, signed-out, empty and failed responses retain distinct states. Account reads share pending requests and a short cache. Tasks, native quota events, explicit refresh and reported reset times invalidate reads. Quota reads do not block startup. Failed refresh retains the previous reading and its observation time.
