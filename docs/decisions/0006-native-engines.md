# Domos 主脑与产品边界

状态：已采用。

Pi Durable 1.4.0 管理持久任务和输入。Bot 选择的原生 Harness 负责模型循环和上下文。Domos 负责身份、完整消息、记忆、技能、定时任务、产品工具和电脑权限。

普通消息、追加输入、定时任务、API 和 CLI 共用 Runtime.submit。requestId 标识一次提交。原生驱动处理模型输入、取消和会话恢复。Domos 产品工具使用 Durable ToolTask。上下文压缩保留完整展示历史。

驱动注册表提供 Pi、Codex、Claude Code、OpenCode 和自定义 ACP。模型与思考档位来自所选原生程序。自定义 ACP 接受程序路径和参数。特殊协议增加驱动。新增 Harness 必须验证实际能力。

原生 Harness 在 Bot 绑定的工作电脑运行。检测、登录和执行使用同一程序及系统用户。优先复用已有 CLI 和原生配置。下载入口安装固定版本到工作电脑的专用目录。保存模型选择后启用该程序。Bot 空闲时才允许切换。服务电脑与工作电脑可以不同。

原生程序保存账号。Domos 保留迁移前的凭据。凭据不会静默复制到工作电脑。管理员管理程序和登录。普通已配对客户端可以选择当前 Harness 的可用模型。

共享电脑工具保留输入验证、审批、用户接管、取消和证据存储。工具身份绑定当前 Bot。电脑工具按顺序执行。变更动作不声明可重放。重启后失效的审批与接管不能执行。已投递但结果不明的操作须先核对。

旧消息、附件、记忆和原生会话文件保留。迁移结算旧任务并保存未完成展示内容。近期历史以有字节预算的引用数据进入模型上下文。conversation_read 提供完整历史读取。

打开旧 SQLite schema 前，Domos 使用 SQLite backup 创建 .v1-backup。随后由上游迁移数据库。回滚必须停止服务，保存当前数据，再恢复匹配旧程序的备份。旧程序不能继续写新版数据库。

首次设置依次选择工作电脑和模型。切换 Harness 创建原生会话，并传入有预算的近期历史。各客户端共享模型选择和审批状态。界面复用 packages/ui 的控件和主题。详细协议、历史预算和官方资料见 [Harness context](../harness-context.md)。
