# 原生任务引擎与产品边界

状态：已采用。

Domos 管理 Bot、配对、工作电脑、权限、产品数据和展示。原生引擎管理循环、基础工具、上下文和会话。Pi 使用 Coding Agent RPC，Codex 使用 app-server，Claude Code 使用原生 CLI stream-json，OpenCode 使用 ACP。引擎注册表提供名称、安装版本和能力。界面不自行推断引擎能力。

所有引擎通过同一个工作电脑进程端口启动。原生电脑使用子进程。Docker 使用容器内进程。控制端使用已鉴权的双向连接。进程期间保持绑定锁。命令、文件和原生会话落在已选电脑中。共享电脑共享操作系统权限和账号目录，各 Bot 分别保存工作目录和原生会话标识。

Pi Durable 的自定义任务记录请求、队列、派发意图、原生轮次、展示事件和结果。引擎内部会话保持原生格式。已派发但未结算的任务先核对原生结果。只有可证明已完成的 Codex 轮次可以补回结果。其他无法确认的任务结束为“执行结果未确认”。不自动重发。重启清除失效审批。

产品工具直接调用现有注册表、ToolTask 和领域方法。MCP 网关绑定工作电脑回环地址，并使用随机访问路径。工具身份由服务绑定到当前 Bot 和外层任务，不接受调用方指定 Bot。工具调用由外层 Durable 任务记录；同一调用标识返回已保存结果。协议请求标识可重复，网关为每次接收的调用分配独立标识。新的协议请求不视为前次调用的自动重试。

服务端密钥沿用现有加密凭据仓库。只把所选账号传给引擎。原生 CLI 需要的账号文件位于工作电脑的持久目录，保留原生刷新机制。此目录由同一电脑上的 Bot 共享，不构成账号隔离。原生进程只继承必要的系统变量与代理设置。敏感输出不写入日志。安装仅由管理员主动发起。

首次设置依次完成身份、电脑和引擎。安装、账号和就绪状态使用现有设置行、表单和主题。可选模型设置折叠。审批卡与当前任务放在一起，所有已配对客户端可看到状态与结果。管理权限控制安装和账号连接。

旧 Bot 默认使用 Pi。旧消息保留。第一个原生会话只带入有长度限制的近期消息，后续使用原生会话恢复。引擎变更仅在空闲时允许，并开始新会话。现有 Pi Durable 库调用入口保留，用于嵌入式调用；桌面、托管 API 和终端聊天统一使用原生引擎。

原生恢复的保证有所收窄。Pi Durable 不再控制引擎内每一次文件或命令操作。没有可核对状态时，系统优先显示不确定结果。用户须核对副作用后重试。引擎进程按任务启动并在结束后关闭。输出有长度上限，展示事件分批提交。

升级前停止任务并备份服务目录及工作卷。旧工作镜像须主动升级到版本 2。回滚时停止新进程，保留升级后快照，再恢复原程序及匹配的升级前备份。不能用旧程序继续执行新任务记录。
